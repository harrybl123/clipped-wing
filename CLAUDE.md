# Clipped Wing — project context for Claude Code

Clipped Wing is a short (about 45 minutes) 2D narrative mystery game played in the browser. Act 1 is being built first. The full design lives in `docs/design-summary.md`; read it before making design-level decisions.

## One-paragraph pitch

A thumbless woodcarver lives in the lower roots of a vast tree whose people worship a glowing tube that runs up its trunk. Offerings go up the tube each morning; blessings come down each evening. When the protagonist's carved bird becomes the first rejection in living memory, they find a picture message hidden inside it, from a stranger outside the tree. Over one week they keep up a secret conversation through hollowed birds while the tree, hungry and frightened, turns them into a scapegoat. Days are for surviving; nights are for solving the mystery.

## Stack

- **Engine:** Phaser (latest stable), TypeScript in strict mode
- **Narrative:** ink, run in the browser with inkjs; `.ink` source compiled to `.json`
- **Build/dev:** Vite
- **Tests:** Vitest, for game logic (state, calendar, save, symbol matching), not rendering
- **Saving:** browser localStorage
- **Hosting:** itch.io (HTML5 build)
- **Version control:** Git + GitHub

## Principles

1. **Text files first.** Everything should be editable as code or data: scenes, areas, characters, messages, symbols, story. Avoid anything that needs a visual editor.
2. **Data-driven.** Areas, characters, messages and decoding symbols live in `src/data/*.json` (or typed `.ts` data modules). Adding content should rarely need new engine code.
3. **One source of truth for story state.** Narrative variables (suspicion, trust, choices) live in ink. TypeScript reads and writes them through the story bridge, never keeps a parallel copy.
4. **Placeholder art until the art pass.** Use simple shapes in the palette below. Never block on art.
5. **Small, verified steps.** After each meaningful change: type-check, run tests, build. Commit at milestones with clear messages.
6. **Don't invent story content.** Use obviously temporary placeholder dialogue unless the task provides the real text. Story decisions belong to the designer.
7. **Ask before adding heavy dependencies** beyond the stack above.

The game is pixel art, so darker and lighter **shades** of these colours are allowed for shading (defined in `src/ui/pixelArt.ts` as `SHADES`). Shades of red follow the same rule as red, and so does copper (the scavenger's hair, Chapter 2's protagonist).

## Working together

Harry is the designer and owns the game: the story, characters, world and design. Others help on branches (see [CONTRIBUTING.md](CONTRIBUTING.md)).

**Git and pull requests**
- **Never commit to or push `main`** unless you're working with Harry in his own clone (his clone has `git config clippedwing.maintainer true`; in anyone else's, a pre-push hook in `.githooks/` refuses pushes to `main`). The repo is public, and GitHub protects `main` too: changes go in by pull request, with Harry's approval and the check passing (Harry, as admin, can still push directly). Work on a branch named `<name>/<short-topic>`, branched from the latest `main`.
- Before opening a pull request: `npm test` and `npm run build` pass. Open it with `gh pr create`, filling in the template, especially **How to try it** (the dev links that show the change). GitHub runs the same checks on every pull request (`.github/workflows/check.yml`).
- Harry tries each pull request and merges it. To try one for him: `gh pr checkout <n>`, `npm install`, then start the dev server.
- One thing per pull request. Record architectural decisions under Decisions below, in the same pull request.

**Working with the designer** (learned with Harry; these apply to everyone's sessions)
- **The designer talks first.** In story planning, summarise what the docs already say in a line or two, then ask for Harry's ideas and build on them. Don't lead with a full breakdown and a list of assumption-based questions.
- **Don't invent story content.** Proposals are welcome, marked **(suggestion)** until Harry confirms them; draft lines are obviously drafts.
- **Placeholder lines keep the mystery.** Characters speak from inside their world (in the tree, the Canopy is paradise and blessings are gifts from above). Never hint at the truth in temporary text; leave that to Harry.
- **The screen matches the text.** Whatever a line says is happening is on screen: people described as there are there before you arrive, people who leave visibly walk off, crowds that look at you exist. Guide the player with the red objective marker, not hint text. Give confrontations a reason and a few beats of build-up; keep optional content short.
- **Every decision is clear and direct:** the player knows exactly what they're choosing and what it means, at the moment they choose (Chapter 2's were confusing). Pose a plain question with options worded as actions, and say what's at stake; big and medium choices keep the second box explaining each option.
- **Roots folk are kind to the lower roots** (a little scorn at most); contempt for them belongs to those in authority (the elders, the preacher).
- **Political choices that change the world around you are these chapters' strength** (designer, 2026-10-14, on Day 1's petition): lean into them. Each duty is a real job with a decision about people's lives, and the world visibly changes because of it (a street's lift mended, a square cleared of its sellers).
- **Harry playtests each day himself** (2026-10-14: browser testing by Claude took too long). Once a day is built: type-check, tests and build, a quick look only where something can't be checked any other way, then hand over the dev links for each part of the day. Fix what Harry finds.
- **Chapter 3 was planned in full before any of it was built** (`docs/sequences/chapter-3/plan.md`, agreed 2026-10-14). Build it in order from Day 1, following the plan; anything that changes the plan goes through Harry first. Plan later chapters the same way.
- British English everywhere in the game. Red, copper and wine are reserved (see the palette).

- **2026-09-30 — Areas are data.** Each area is a typed `AreaDefinition` in `src/data/areas/` (registered in `index.ts`), built by one generic `AreaScene` (start it with `{ areaId }`). It holds: the carved `cavity` (heartwood outside it), `solids` (`oneWay` platforms can be jumped up through; `invisible` ones aren't painted), dithered `lights`, baked `lines` and `props` (row sprites), animated `features` (`fire`, `swing`, `drip`, `jars` driven by an ink variable), `people` and `interactables` (each runs an ink knot; the nearest one on the same surface shows an `[E]` prompt). `src/ui/paintArea.ts` paints the backdrop from the data. Area art is small and dense (about one screen, lots of character) rather than big empty halls. `tests/areas.test.ts` checks every area: sprites well-formed, props in bounds, things standing on solids, and every knot and variable existing in the compiled ink. Area knots live in `story/<area>.ink`, INCLUDEd from `main.ink`. The player controller is `src/objects/Player.ts`.

- **2026-09-30 — Pixel art.** The whole game is 2D pixel art at a native **480×270**, with `pixelArt: true` and `roundPixels`, scaled up by whole numbers only (`integerZoom()` in `config.ts`, re-applied on window resize) so pixels stay square. Physics is scaled to match (gravity 450). Colours come from the palette plus `SHADES` (`src/ui/pixelArt.ts`); dithered backdrops never use red. **Backdrops** are painted per pixel in code: a scene supplies `colourAt(x, y)` (base wood, grain, vignette, light sources via `falloff`/`addLight`), and `makePaintedTexture` ordered-dithers it to `BACKDROP_PALETTE`. **Sprites** are rows of characters in `src/ui/sprites.ts`, turned into textures with `makeSpriteTexture` or stamped into backdrops with `stampRows`. **Text** uses a hand-drawn 5×7 pixel font (`src/ui/pixelFont.ts`, pure and unit-tested) through the `PixelText` game object, never Phaser's `Text`. The palette lives in a Phaser-free `src/palette.ts`, re-exported by `config.ts`. This supersedes the 1920×1080 painterly rendering below. Parked menu/flow ideas are in `docs/ideas.md`.

- **2026-09-29 — Hosting.** `npm run package` zips the contents of `dist/` (with `index.html` at the zip root) into `clipped-wing.zip`, which is gitignored. The build is one JS bundle plus `index.html` with relative paths, and has been checked running from a nested URL path. Dev-only code is guarded with `import.meta.env.DEV` and stripped from the build.

- **2026-09-29 — Scenes and UI.** The scene flow is `Boot` → `Preload` → `Title` → `Area` (New Game starts at home; TestArea was removed when areas became data). `BootScene` creates the shared **session** `{ story, calendar, saves }` (`src/session.ts`) and stores it in the Phaser registry. Scenes get it with `getSession(this)`. `saveSession`/`loadSession` wrap SaveSystem and return player-facing messages. Placeholder textures are generated in code (see the pixel art decision). `DialogueBox` (`src/ui/`) grows upwards when a long line and its choices won't fit (its bottom edge stays put), and plays a knot through StoryBridge: Space/Enter/E/click to advance; choose with up/down or W/S then Space/Enter/E (the selected choice is amber; no cursor, since an arrow beside one option reads as a recommendation), number keys, or click; blank ink lines are skipped. `DebugOverlay` is toggled with the backtick key; its keys (T time, U afternoon action, K save, L load, X delete save) only work while it's visible, and save/load are refused mid-conversation. Gotchas: children of a `scrollFactor(0)` container also need `scrollFactor(0)`, or input hit-tests are offset by the camera scroll. Always read `JustDown` every frame so presses don't queue while input is blocked. Dev builds expose the game as `window.__game` for console debugging.

- **2026-09-29 — Core systems** (`src/systems/`, no Phaser imports, unit-tested in `tests/`).
  - **StoryBridge** is the only code that touches inkjs. It never caches variable values. Getting or setting an undeclared variable throws, which catches typos. Variable names are read from the compiled JSON's `global decl` because inkjs has no public API for this. Observers also fire after `loadState` (ink itself doesn't do this). A failed `loadState` keeps the previous state. `nextLine()` returns `{ text, tags }`.
  - **Calendar** runs from `prologue` to day 7 × `morning | afternoon | evening | night`, starting on the prologue morning. Every day, including the prologue, has all four slots; the game decides which to skip. Day 1 has unlimited afternoon actions, other days have `AFTERNOON_ACTIONS_PER_DAY` (2). `advance()` returns false at day 7 night.
  - **SaveSystem** writes one localStorage key (`clipped-wing:save`) holding `{ version, savedAt, calendar, ink }`, where `ink` is ink's own state JSON. `SAVE_VERSION` is currently 1. It never throws: failures come back as `unavailable | missing | corrupt | outdated | write-failed`. Storage is injectable for tests.
  - **SymbolMatcher** compares guesses after normalising them (lowercase, strip punctuation and apostrophes, drop a/an/the) and applying a simple suffix stemmer to both the guess and the accepted words. Irregular forms ("saw") must be listed explicitly. Wrong attempts are counted per symbol, with `NUDGE_AFTER` = 2, `HINT_AFTER` = 4, `LETTER_AFTER` = 5 (from then each wrong attempt reveals one more letter of the first accepted word, `revealedLetters`) and `AUTO_SOLVE_AFTER` = 8. Blank guesses don't count. The glossary answer is the player's own words, or the first accepted word if auto-solved.

- **2026-09-29 — Ink pipeline.** `scripts/ink.mjs` compiles `story/main.ink` (plus its INCLUDEs, resolved relative to `story/`) with inkjs's own compiler (`inkjs/full`). No external binaries. Output goes to `src/generated/main.ink.json`, which is gitignored and imported directly by the game so no runtime fetch or asset path is needed. A Vite plugin in `vite.config.ts` runs it at dev start, on every `.ink` change in dev (errors go to the terminal and Vite's browser overlay, and the last good JSON is kept), and at build (an error fails the build). Errors print as `story/file.ink:LINE  message`. The script is plain JS checked by TypeScript (`checkJs`). The root ink flow does nothing; the game starts conversations by knot name.
